PRD — Sprint 002 · migrate-tests-nunit-fluent

5 goals 7 stories 28 AC 7 non-goals updated 2026-06-04

Problem

The Source/LordKuper.Common.Tests project (net472) is written against xUnit, with all assertions in Assert.* form and a custom xUnit-specific test-framework seam ([assembly: TestFramework] + a RimWorld AssemblyResolve handler). The project standardizes on NUnit + FluentAssertions for more expressive, diff-rich assertions and a maintainable runner setup. The migration must swap the framework, the assertion library, the custom test infrastructure, and the local coverage tooling together — while preserving the suite's behaviour and overall coverage. Getting any one layer wrong (most notably the assembly-resolver timing) presents as mass test failure rather than an obvious wiring bug, so the requirements below are framed as concrete, verifiable checks across every affected layer.

Goals

  1. G1

    Replace the xUnit package stack with NUnit + NUnit3TestAdapter + FluentAssertions 7.x in the test project, leaving the rest of the build governance intact.

  2. G2

    Migrate every test attribute and every Assert.* call site to NUnit attributes and FluentAssertions .Should() form, preserving behaviour and the three intentionally-skipped tests.

  3. G3

    Re-implement the custom RimWorld test infrastructure (assembly-resolve seam and static-state isolation) under NUnit with the same load-bearing contract.

  4. G4

    Keep the suite building warning-clean under TreatWarningsAsErrors and fully discoverable/green under the NUnit3 adapter, with overall coverage equivalent.

  5. G5

    Update the local coverage harness (scripts/coverage.ps1) and command registry so coverage runs correctly under NUnit; no in-repo CI workflow is added.

User stories

Maintainer 4
  • as a maintainer, I want the test project to reference NUnit, NUnit3TestAdapter and FluentAssertions 7.x instead of xUnit, so that the suite runs on the standardized, free-licensed stack. (AC-1 … AC-4)
  • as a maintainer, I want all xUnit attributes mapped to NUnit equivalents with the skipped tests preserved, so that the same set of tests exists and runs (or is intentionally ignored) after the swap. (AC-5 … AC-9)
  • as a maintainer, I want every Assert.* call replaced by an equivalent FluentAssertions .Should() assertion, so that failures are more readable and the assertion intent is preserved. (AC-10 … AC-16)
  • as a maintainer, I want the migration to be a behaviour-preserving refactor with overall coverage held equivalent, so that the swap does not silently weaken or change what the suite verifies. (AC-17, AC-18, AC-26)
Test engineer 2
  • as a test engineer, I want the RimWorld AssemblyResolve seam re-implemented so it registers before any RimWorld-typed test class loads under NUnit, so that RimWorld/Unity-referencing tests resolve their types instead of failing at discovery. (AC-19 … AC-21)
  • as a test engineer, I want the StaticState snapshot/restore isolation preserved under NUnit per-test setup/teardown with no cross-test bleed, so that tests touching shared statics stay deterministic and serialized. (AC-22 … AC-25)
Maintainer (coverage) 1
  • as a maintainer, I want the local AltCover coverage script and command registry to work with the NUnit3 adapter, so that I can still measure coverage locally after the migration. (AC-27, AC-28)

Acceptance criteria

Each criterion is one testable assertion. Area chips: packaging, attributes, assertions, infra, isolation, build/run, coverage. Counts referenced below are the audited current-state figures: 132 [Fact] (129 executed + 3 [Fact(Skip=…)]), 3 [Theory] expanding to 13 [InlineData] cases, and 236 Assert.* call sites across 12 distinct methods in 11 files; the migration must account for every one.

This PRD table is the canonical home of the mapping; other artifacts (e.g. ADR-0005) link here rather than duplicate it. All 12 distinct xUnit assert methods in use are listed; no other Assert.* method (Same, IsType, Collection, Raises, Multiple) appears in the suite.

UX / UI

Not applicable. This sprint is a test-suite migration with no user-facing surface — no UI, no UX flows, no mockups, no design system changes. UX-spec and accessibility artifacts are out of scope for this sprint.

Non-goals

  • Adding new test coverage beyond the existing suite — coverage stays equivalent overall, not expanded.
  • Changing production code in Source/LordKuper.Common except where strictly required by the migration.
  • Adding any in-repo CI workflow (.github/workflows/, pipeline YAML); the "CI config" scope reduces to scripts/coverage.ps1 + .asd/project/commands.yaml only.
  • Migrating to FluentAssertions 8.x or any commercially-licensed assertion library — pinned to 7.x (Apache-2.0).
  • Deleting or permanently disabling the 3 RimWorld-context-dependent tests — they remain present as [Test, Ignore(...)].
  • Changing build governance (Directory.Build.props: TreatWarningsAsErrors, WarningLevel, Nullable), the RimWorld reference set, or the production project reference.
  • Editing persistent design docs (xUnit/coverlet tech-references, stack.html, ADR-0001) or project rules (custom-coding-rules.md, custom-common-rules.md) in place — those updates route through the normal design → design-promote flow and are tracked in the audit's documentation migration plan, not this PRD.
