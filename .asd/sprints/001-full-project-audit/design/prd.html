PRD sprint draft

PRD — Sprint 001 · full-project-audit

4 goals 8 stories 27 AC 8 non-goals updated 2026-06-03

Problem

LordKuper.Common is a brownfield RimWorld utility library consumed by other mods, but a full-project audit (sprint 001, shape B) found it drifting from the project's own .asd/rules/* workflow rules and the three custom rule files. Twelve concrete improvement opportunities (IMP-01 … IMP-12) were triaged: stale build scaffolding, a silent null-StatDef resolution in WorkTypeStatMap, order-dependent scoring with no determinism contract, a Tests project outside zero-warnings/nullability governance, design-doc drift versus About.xml, and a near-total absence of automated test coverage against the code-style §17 80% floor. The ADR phase (2026-06-03) closed several items by decision: the audit's data-driven FAIL on the WorkTypeStatMap default weights is reclassified as NOT a violation (IMP-07 reduced to a warning log — see the IMP-07 reframing rationale); the StatRanges order-dependence is kept adaptive and documented (IMP-08 option b); the LangVersion pin is dropped (IMP-03 won't-do, latest retained); and 1.5 localization parity stays won't-do (1.5 is a frozen archive, IMP-09). This sprint converts the remaining findings into a verifiable, traceable requirement set so the library is brought into rule compliance, made safe to extend, and trustworthy for the mods that depend on it — without regressing public behavior beyond intentional, enumerated API changes.

Goals

  1. G1

    Rule compliance & clean build. Bring the codebase into compliance with the custom coding/design rules — zero-warnings and Nullable=enable governance extended to the Tests project, machine-specific RimWorld-path fallback removed with fail-fast, and stale build scaffolding cleaned — so a clean rebuild is provably warning-free and reproducible. (LangVersion=latest is retained by decision; the SDK-drift risk is accepted, see Risks.)

  2. G2

    Observable & deterministic core. Make the WorkTypeStatMap seed-default weights observable on null StatDef resolution (warning log instead of silent no-op; the weights stay in code as overridable seed defaults by design — see the IMP-07 reframing rationale), and resolve the adaptive StatRanges order-dependence per the recorded ADR decision (kept adaptive, documented), so stat scoring is rule-compliant and its determinism characteristics are explicit to consumers.

  3. G3

    Maintainability & SSoT. Collapse heavy DRY violations (tooltip fields, PawnFilter.Combine), and reconcile design docs (stack.html/concept.html) to the authoritative About.xml so each fact has a single source of truth.

  4. G4

    Test coverage to the 80% floor. Introduce a RimWorld-context isolation seam with order-independent static-state save/restore, and build comprehensive tests across the stateful subsystems sufficient to reach the code-style §17 floor of ≥ 80% Coverlet-measured line coverage on the Source assembly.

User stories

Maintainer 5
  • as a maintainer, I want a clean, reproducible warning-free build across both Source and Tests projects, so that I can trust TreatWarningsAsErrors as a real quality gate rather than a flag that only covers half the solution.
  • as a maintainer, I want a missing/renamed vanilla StatDef referenced by the WorkTypeStatMap seed-default weights to fail visibly (warning log) rather than silently no-opping, so that a vanilla stat removal surfaces in the log instead of degrading scoring silently (the seed-default weights stay in code by design — see the IMP-07 reframing rationale).
  • as a maintainer, I want the StatRanges normalization behavior resolved and recorded in an ADR, so that the determinism contract of scoring is an explicit, reviewed decision rather than incidental code behavior.
  • as a maintainer, I want a RimWorld-context isolation seam and order-independent static-state save/restore in the test harness, so that the stateful subsystems become testable and the suite stays reliable regardless of test execution order.
  • as a maintainer, I want design docs reconciled to the authoritative About.xml, so that supported versions, dependencies, and soft integrations have one source of truth and cannot drift.
Consuming-mod developer 3
  • as a consuming-mod developer, I want the observation-order dependence of StatRanges/WorkTypeThingRule scoring documented on the public members' XML docs, so that I know a given Thing's score depends on the set of observations seen so far before I depend on it.
  • as a consuming-mod developer, I want any breaking public-API change to be intentional and enumerated in the PR, so that I can update my mod deliberately against a clean API instead of being surprised by silent surface changes.
  • as a consuming-mod developer, I want the library covered by a real test suite at the 80% floor, so that I can upgrade the dependency with confidence that core stat, filter, time, and cache behavior is regression-guarded.

Architectural decisions for ADR

These decisions were escalated to the ADR phase; the resolutions recorded on 2026-06-03 are reflected below. The PRD records the requirement; the ADR records the chosen option.

ADR-0001 · RimWorld-context isolation seam
The abstraction/seam strategy for testing DefDatabase/game-context-bound code, and the static save/restore mechanism. Owns AC-13 (seam abstracts DefDatabase), AC-14 (save/restore fixture wired), AC-18 (seam recorded before build-out), and gates the AC-20/AC-21 build-out.
ADR-0002 · StatRanges adaptive determinism
RESOLVED — option (b) (2026-06-03). The adaptive running-min/max behavior is kept; the observation-order dependence is documented on the affected public members' XML docs (AC-9). The static Ranges cache is retained and save/restored by the test fixtures (AC-16). No make-deterministic work and no reproducibility test are in scope.
ADR-0003 · Build governance
The build-time governance for the RimWorld path: the machine-specific default is removed and the build fails fast with a clear message when neither RIMWORLD_DIR nor RimWorldDir resolves to an existing directory (AC-2), alongside the Tests-project zero-warnings/nullable governance (AC-3) and clean-rebuild gate (AC-5).
Considered & dropped · Work-type stat-weight Def/config schema
DROPPED — no live ADR record. A data-driven Def/config surface for the WorkTypeStatMap weights was considered and dropped: the weights are intentional seed defaults, not hardcoded balance (see the IMP-07 reframing rationale), so no schema is introduced and no ADR is opened. Provisional label ADR-A is retired.

Risks & notes

  • 80% on RimWorld-context-bound code is a large effort gated by the ADR-0001 isolation-seam decision (AC-18): much of the Source assembly requires the seam before it can be exercised, so the coverage floor (AC-21) cannot start in earnest until the seam lands.
  • SDK-drift risk accepted on LangVersion=latest (IMP-03 won't-do, user decision 2026-06-03): the language version is intentionally not pinned, so a future SDK bump could change semantics under warnings-as-errors. The clean-rebuild gate (AC-5) is expected to catch such drift at build time rather than a pin preventing it.
  • Doc edits route through the design pipeline (AC-12): the BA does not author persistent design/ directly; the doc-owning step executes IMP-10 edits.
  • backward_compat=none: breaking public-API changes are permitted; any taken must be intentional and enumerated in the PR (AC-26), optimizing for a clean API over source compatibility.

Non-goals

  • RimWorld 1.5 is a conserved archive — its localization and content are intentionally frozen; no 1.5 parity, translation, or key sync is in scope. (1.5 remains listed in supportedVersions per AC-23, but is not modified — resolves IMP-09 as won't-do.)
  • Moving WorkTypeStatMap default weights to a Def/config surface is out of scope — they are intentional seed defaults overridden by consumer-mod persisted settings (IExposable StatWeight/WorkTypeThingRule), not hardcoded balance. IMP-07 is reframed to the null-stat warning log (AC-8) only; no Def schema is introduced. (User decision 2026-06-03.)
  • No new feature scope. This sprint is audit-remediation (shape B); no new product capability is introduced.
  • No UX flows, mockups, or visual design. UI widgets are touched only as incidental to DRY/refactor ACs; their immediate-mode draw behavior is preserved, not redesigned.
  • No source-compatibility guarantee. Under backward_compat=none, preserving the existing public API signatures is explicitly not a goal; clean API wins over source-compat.
  • No Steam Workshop / publishing changes (PublishedFileId.txt, Preview.png, About.xml identity) beyond keeping design docs reconciled to About.xml.
  • No live RimWorld-runtime / integration testing. Coverage is unit-level via the isolation seam; an in-game smoke test is not in scope for the AC-21 floor.
  • No reverse-engineering of new persistent design docs. concept.html/stack.html already cover the brownfield prose; only reconciliation edits (Cluster E) are in scope, not net-new design documents.
