Concept — rimworld-common

2 pillars 2 anti-pillars updated 2026-06-03

Vision

A single shared .NET class library that consolidates the cross-cutting building blocks RimWorld mods repeatedly need — definition and stat caches, pawn and stat helpers, reusable filters and custom-stat models, and a consistent IMGUI widget toolkit — so each dependent mod implements its own features instead of re-solving the same plumbing.

Target users

  • Dependent RimWorld mods — consume the shared assembly to obtain caching, helper, filter, custom-stat, and UI primitives rather than maintaining their own copies, keeping behaviour and look-and-feel consistent across the mod family.
  • The library's own maintainer — develops and evolves dependent mods against one versioned common surface, fixing or extending shared logic in a single place.

Value proposition

Dependent mods get a ready-made, RimWorld-aware foundation: timed and definition caches for hot-path lookups, helpers over pawns/stats/defs/math/text, composable pawn and limit filters, melee/ranged/tool custom-stat models, and a unified widget set (buttons, fields, sliders, selectors, tabs, scroll views, pawn boxes). This removes duplicated plumbing, centralizes Harmony-based RimWorld integration, and yields consistent UI and behaviour across every mod that links it. It also ships optional, reflection-guarded integration with Vanilla Skills Expanded that activates only when that mod is present (integration details live in stack.html).

Pillars

  • Reusable shared foundationCross-cutting concerns (caching, helpers, filters, custom stats, UI) live once in a versioned assembly and are consumed by many mods, never copy-pasted per mod.
  • RimWorld-native integrationBuilt directly against the game's managed assemblies and Unity IMGUI, with Harmony available for runtime patching, so primitives speak RimWorld's own types (Pawn, Def, Stat) and UI idioms.

Anti-Pillars

  • Not a standalone player-facing modThis is a library, not a gameplay mod — it ships no features players enable on their own; value is realized only through dependent mods that reference it.
  • Not a general-purpose / cross-game frameworkScope is deliberately bound to RimWorld and its API surface — it does not aim to be a portable utility library independent of the game.

Constraints

  • Targets net472 to match the RimWorld runtime; cannot adopt newer target frameworks the game does not load.
  • Depends on game-managed assemblies resolved from $(RimWorldManagedDir) (Assembly-CSharp, UnityEngine modules) — builds require a local RimWorld install path.
  • Harmony is referenced for patching but excluded from runtime output (PrivateAssets=all, ExcludeAssets=runtime) — the host environment must provide Harmony at load time.
  • Supports multiple RimWorld versions (currently 1.5 and 1.6) via version-specific folders: per-version assemblies, languages, and content ship under version-named directories (1.5/, 1.6/), with the build emitting into the matching <version>/Assemblies/ folder. New RimWorld versions are onboarded by adding a new version folder rather than breaking existing ones.
  • Warnings-as-errors at maximum warning level on all configurations — code must stay clean to compile.
