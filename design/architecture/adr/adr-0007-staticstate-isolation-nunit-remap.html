ADR-0007 · StaticState isolation: xUnit [Collection]/IDisposable → NUnit [SetUp]/[TearDown] + [NonParallelizable]

approved subsystem: project updated 2026-06-04
approved subsystem: project ADR-0007

Context

Three test classes (StatWeightTests, StatefulSubsystemTests, StatRangesTests) touch shared static caches and isolate via the xUnit seam introduced in ADR-0001: StaticStateFixture : IDisposable snapshots DefProvider.Current and restores it (rebuilding StatHelper, WorkTypeStatMap, and reflection resets of SkillStatMap._map, PassionHelper.{_isInitialized,_cachedPassions,PassionCache}, StatRanges.Ranges); StaticStateTestBase drives it per-test via ctor + Dispose; and a [CollectionDefinition("StaticState", DisableParallelization=true)] + [Collection("StaticState")] serializes the classes. ADR-0001 was deliberate that per-test ctor+Dispose (not per-class IClassFixture) gives true per-test isolation. The migration must preserve the isolation contract (the exact snapshot/restore set) while re-expressing the xUnit lifecycle vocabulary in NUnit (PRD AC-22 … AC-25). This makes ADR-0001's xUnit-specific prose inaccurate; that ADR is approved and persistent, so its wording is remapped in place during this design-promote step (not edited silently).

Decision

Re-express the ADR-0001 isolation seam in NUnit: keep the snapshot/restore body verbatim, drive it from per-test [SetUp] (snapshot) / [TearDown] (restore), and replace the xUnit collection-serialization with NUnit's default non-parallel execution (made explicit via [NonParallelizable]).

  • Snapshot/restore preserved verbatim (AC-22): the set of snapshotted/restored statics — DefProvider.Current; rebuild of StatHelper and WorkTypeStatMap; reflection resets of SkillStatMap._map, PassionHelper.{_isInitialized,_cachedPassions,PassionCache}, and StatRanges.Ranges — is unchanged. This body is framework-agnostic and is the actual isolation contract from ADR-0001 (and the StatRanges.Ranges entry exists because ADR-0002 keeps that cache mutable). The reusable logic stays in the renamed StaticStateFixture type; only its invocation mechanism changes.
  • Per-test lifecycle remap (AC-23): StaticStateTestBase's constructor → [SetUp] (build the fixture / snapshot); its Dispose() → [TearDown] (restore). NUnit [SetUp]/[TearDown] are per-test, matching the original ctor+Dispose per-test granularity exactly — the deliberate ADR-0001 choice over per-class IClassFixture is preserved.
  • Serialization remap (AC-24): drop [CollectionDefinition("StaticState", DisableParallelization=true)] and [Collection("StaticState")]. NUnit runs non-parallel by default (this project sets no [Parallelizable]/[assembly: Parallelizable]), so the static-touching classes are already serialized. Apply [NonParallelizable] to the three classes anyway, as an explicit, self-documenting statement of intent (belt-and- suspenders against a future accidental opt-in to parallelism).
  • Relationship to ADR-0001. This ADR supersedes the xUnit-specific wording of ADR-0001 (StaticStateFixture via IClassFixture, [Collection] serialization, IDisposable snapshot/restore) — not ADR-0001's isolation contract or its IDefProvider/InternalsVisibleTo decisions, which stand unchanged. ADR-0001's mechanism prose is remapped in place during this design-promote step; ADR-0001 is not marked superseded as a whole — only its mechanism vocabulary is updated, with a cross-link to this ADR.
  • No cross-test bleed (AC-25): running the full suite repeatedly and in any order yields the same results; the 8 plain (non-isolated) classes are unaffected by the seam.
  • The InternalsVisibleTo grant and the internal reset/snapshot hooks from ADR-0001 remain in force; this remap introduces no new abstraction, layer, or dependency, so no fresh Complication Approval is needed.

Consequences

Positive

  • Isolation contract is preserved bit-for-bit; only the lifecycle vocabulary changes, so the risk of altering what the suite verifies is minimal.
  • NUnit's non-parallel-by-default removes the need for an explicit serialization construct; [NonParallelizable] is documentation, not load-bearing wiring — simpler than the xUnit collection machinery.
  • Per-test [SetUp]/[TearDown] map 1:1 to the original per-test ctor+Dispose, keeping the deliberate per-test (not per-class) granularity from ADR-0001.

Negative

  • Approved-ADR remap: ADR-0001 (approved, persistent) described the seam in vocabulary the code no longer uses. The wording is remapped in place during this design-promote step, keeping the contract unchanged so only mechanism prose moves; the cross-link records the relationship.
  • Relying on NUnit's non-parallel default is implicit: if anyone later adds [Parallelizable] at assembly scope, the static-state suites would race and the snapshot/restore isolation would break. [NonParallelizable] on the three classes is the explicit guard, but a global parallel opt-in could still mis-order setup; the tech-reference notes "do not add [assembly: Parallelizable]".
  • The reflection-driven reset set is a maintained contract: if production adds a new static cache, the snapshot/restore set must be extended in lockstep or new cross-test bleed appears — same standing obligation as under xUnit, carried forward unchanged.
  • The StaticStateTestBase ctor→[SetUp] / Dispose→[TearDown] rewrite is behavior-sensitive (ordering of snapshot vs. test body); must be verified by repeated/random-order full runs (AC-25), not inspection.

Alternatives considered

  • Per-class [OneTimeSetUp]/[OneTimeTearDown] (snapshot once per class) — rejected: coarsens isolation to per-class, reversing ADR-0001's deliberate per-test choice; a test that mutates statics could then leak into the next test in the same class.
  • Keep a serialization marker analogous to [Collection] (e.g. an explicit single-threaded fixture) — rejected: redundant given NUnit's non-parallel default; adds machinery for no behavioral gain.
  • Mark ADR-0001 fully superseded and re-state the whole isolation decision here — rejected: ADR-0001's contract (IDefProvider, the snapshot set, InternalsVisibleTo) is unchanged and still authoritative; only the mechanism vocabulary moves, so a scoped vocabulary remap is correct, not a wholesale supersession.

Acceptance criteria satisfied

  • AC-22 — the snapshot/restore set (DefProvider.Current; StatHelper/WorkTypeStatMap rebuild; reflection resets of SkillStatMap, PassionHelper, StatRanges.Ranges) is preserved verbatim.
  • AC-23 — per-test ctor/Dispose remaps to per-test [SetUp]/[TearDown], preserving per-test granularity.
  • AC-24 — xUnit [Collection] serialization drops to NUnit non-parallel default, made explicit with [NonParallelizable] on the three classes.
  • AC-25 — repeated/random-order full runs yield identical results; the 8 plain classes are unaffected.
